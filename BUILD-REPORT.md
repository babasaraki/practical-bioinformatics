## Print layout

The first print build rendered without error and was still wrong on the page.
`scripts/check_pdf_layout.py` run against that build - 556 pages - reports
**overlapping text on 42 of them**, 13,728 colliding character pairs in all, and text
set below the bottom margin on 20. Attributing those 42 pages to their cause: 18 in the
glossary and 2 more in Appendix C, where definition lists are used; 16 where a callout
overflowed and the following text was set on top of it; and 6 part pages, where the
title ran under the roman numeral. The 20 pages with text below the bottom margin are
the 16 callout pages plus 4 more where a callout overflowed without anything being set
over it. Six faults account for all of it, every one in how the Typst book template and
Quarto's own rules interacted. `tex/typst-show.typ` carries the corrections, each
with the reason beside it.

| Fault | Cause | Correction |
|---|---|---|
| Solutions callouts overflowed the foot of the page, with following text set on top of them — 16 overlap pages, and all 20 of the pages with text below the bottom margin | Quarto defines callouts with `breakable: false`; a block that cannot break and does not fit is not reflowed, it spills | Callout redefined with the three blocks breakable |
| Part titles ran under the roman numeral — 6 part pages | Template numeral defaults to 16 em, wider than the 40% of the text block left to it once the numeral has three glyphs | `part-font-size: 5em` |
| The part page's contents list grew up into the title | At the default depth it lists every section of every chapter in the part | `outline-small-depth: 1`, chapters only |
| Glossary definitions were printed over their own terms — 18 pages in the A–Z, and 2 in Appendix C, which uses the same definition lists | Quarto's `terms.item` rule pulls the definition up by `inset: (top: -0.4em)`, which assumes its own template's looser spacing | Rule re-emitted without the negative inset |
| Paragraphs ran together with no separation | Template sets paragraph spacing equal to its leading, and first-line indentation is off | `par(spacing: 1em)` |
| Part titles hyphenated across lines | `hyphenate: true` was forced globally; the part page sets `justify: false`, where Typst would not hyphenate by default | `hyphenate: auto` — justified text only |

A stray folio was also being printed on the title verso 6.6 pt below the trim edge:
`footer: none` was set after the template had already generated its own front matter.
It now precedes the template.

`scripts/check_pdf_layout.py` is the check that found these. It reads the rendered PDF
and tests three things a word count cannot see — that every page is 6 × 9 in, that no
two characters on different lines collide, and that nothing is set below the bottom
margin. On the shipped PDF all three pass:

```
592 pages | page sizes found (in): [(6.0, 9.0)]

PASS  every page is 6.0 x 9.0 in
PASS  no overlapping text
PASS  no text below the bottom margin
```

The five pages it notes as having one or two touching glyph boxes are ligature
kerning in `fi` and `fo` pairs, not layout faults.

## Deliberate limitations, recorded by the chapter authors

- **Chapter 10** computes secondary-structure content from backbone φ/ψ angles rather
  than with DSSP, which is not installed; the text and the figure caption both say so.
- **Chapter 10** describes an AutoDock Vina run without running it — Vina is not
  installed, and no score is quoted anywhere.
- **Chapter 12**'s class-imbalance and multiple-testing demonstrations use simulated
  data, because no bundled dataset carries a rare labelled class. Both are labelled as
  simulations in the prose.
- **Chapter 11**'s rank-based enrichment ranks only the 30 genes of the bundled STRING
  subnetwork, since the bundle holds no genome-wide ranked list; the chapter says so.
- **Chapter 13** hard-codes ten TP53 exon-block coordinates retrieved from Ensembl
  (ENST00000269305, GRCh38) that are not in `data/MANIFEST.tsv`. Their provenance and
  retrieval date are stated, and the chapter validates them against the bundled
  GenBank CDS length and five canonical TP53 variants.
- **Chapter 14** is about 30% over the chapter word budget. One compression pass was
  applied; further cuts would have dropped a required topic.
- The **bundled read files are simulated** from the bundled reference, with a fixed
  seed. This is stated wherever they are used and in Appendix C. Their true origin is
  encoded in each read name, which lets Chapter 9 check an alignment against ground
  truth — something real data never allows.

## Bibliography

154 entries. Each was resolved against Crossref or OpenAlex with the first-author
surname, publication year and — after an early failure — the publication venue
verified, then replaced with the registration agency's own BibTeX record fetched by
DOI, so author names and page ranges are as the publisher registered them.

Two entries in the first build resolved to digest items in *Yearbook of Paediatric
Endocrinology* that share a title with the article the book cites: the human pangenome
paper and the gnomAD constraint paper. A chapter author found this, declined to cite
them, and reported it. Both are corrected, and `scripts/add_references.py` now checks
the venue so the error cannot recur. Six entries carry no DOI because none is
registered (two JMLR articles, the R manual, FastQC, igraph, and Dayhoff's *Atlas*);
each is marked with a `note` field.

### A note on citation keys and years

Citation keys in this book carry the year a work is conventionally cited by, which
for 35 of the 154 entries is one year later than the `year` field in the entry
itself. That is not an error: registration agencies record online-first publication,
while the citation convention follows the issue. The *Nucleic Acids Research* 2022
database issue, for instance, is registered as 2021. Keys are opaque labels and never
appear in the rendered text, which always shows the entry's own year, so the two can
differ without any reader-visible inconsistency. Where a key and its entry can be
made to agree without departing from convention, they have been.

Reproduce the whole bibliography with:

```bash
python scripts/build_bibliography.py      # Crossref, with author and year checks
python scripts/resolve_openalex.py        # OpenAlex for what Crossref cannot find
python scripts/normalise_bibliography.py  # registrar BibTeX by DOI
python scripts/add_references.py          # venue-checked additions and corrections
```

## Toolchain notes for whoever builds this next

- **The print PDF is produced by Typst, not LaTeX.** No TeX distribution could be
  installed in the environment this book was assembled in: TinyTeX's installer fails
  against this Quarto build, and conda's `texlive-core` ships binaries with no package
  tree and a broken `tlmgr`. Typst ships inside Quarto, needs nothing else, and
  produces the 6 × 9 in interior directly. The full LaTeX configuration is written and
  kept as a profile — `quarto render --profile latex` — for a machine that has TeX,
  and `tex/preamble.tex` is annotated with the one-line change that switches it to
  `krantz.cls` when CRC supplies it.
- **The book uses the knitr engine throughout**, declared in every chapter's YAML
  header. Quarto's per-file engine detection would otherwise choose Jupyter for the
  Python chapters, and a Jupyter kernel cannot start in a sandbox that forbids binding
  a local socket. Python chunks run through `reticulate`; set `RETICULATE_PYTHON` to
  the environment's interpreter.
- **The print PDF renders code without syntax colour.** Quarto's highlighter emits
  listings through a custom Typst function rather than as `raw` blocks, which puts
  them beyond the reach of any styling rule and leaves them justified — stretching the
  spaces inside a listing until its indentation no longer lines up. Setting
  `highlight-style: none` for the Typst format hands highlighting to Typst, whose
  output is a real `raw` block that `tex/typst-show.typ` styles correctly. Monochrome
  listings also suit a black-and-white print interior, which is substantially cheaper
  to produce. HTML and EPUB keep full colour highlighting.
- **The 6 × 9 trim comes from `tex/typst-show.typ`**, a template partial that passes
  explicit `width`, `height` and `margin` to the `orange-book` template. Setting
  `papersize` alone does not work: the template applies its own page rule after both
  the Quarto page rule and any header include, so geometry set anywhere else is
  silently overridden.
